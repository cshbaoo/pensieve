# CRD:跨设备工作交接(Work Handoff)

| 项 | 内容 |
|---|---|
| 文档类型 | CRD(概念需求文档,PRD 前置) |

| 日期 | 2026-08-18 |
| 依赖版本 | Pensieve v0.3.0+ |

---

## 1. 背景与问题

开发者在 A 设备(如公司电脑)开发需求到一半,下班不带电脑,想在 B 设备(家里电脑)无缝续接。当前丢失的不是代码,而是**工作心流**:

| 丢失内容 | 现有手段能否找回 |
|---|---|
| 需求目标、为什么这么做 | ❌ 对话记录留在 A 设备 |
| 做到哪一步(含未提交改动) | 🟡 git log 无法覆盖未提交部分 |
| 下一步行动、验收标准 | ❌ |
| 当次踩坑、临时决策 | 🟡 需手动沉淀为记忆 |
| 未提交的代码改动 | ❌ 电脑不在身边即不可达 |

Pensieve 已具备记忆沉淀、git 同步、密钥扫描、draft 确认等基建,但缺少对**短时任务状态**(区别于长期知识)的表达。

## 2. 需求目标

**一句话:下班前一句话交接,回家后一句话续接。**

- 交接动作成本 ≤ 30 秒(对 agent 说"我下班了"即可完成)
- 续接无需人工搬运任何文件/聊天记录
- 不新建任何同步通道,全部复用现有 git sync

### 成功指标(dogfood 期观察)

- handoff-listing:周人均 handoff 使用次数
- resume 成功率:交接被 B 设备消费且 agent 无需追问基础背景的比例
- 误同步拦截:因合规守卫(密钥/local-only)被拒绝的写入次数(应接近 0 漏网)

## 3. 目标用户与场景

**主用户**:多设备独立开发者 / 跨办公地点的公司员工。

**核心场景**:

1. **交接(A 设备)**:开发中途下班,对 agent 说"我下班了,做个交接"→ 生成 handoff → 确认 → 推远端。
2. **续接(B 设备)**:`pensieve sync` 后 `memory_context` 简报顶部出现 active handoff 横幅;对 agent 说"继续昨天的需求"→ agent 读取交接全文与关联记忆直接开工;handoff 自动标记 consumed。
3. **过期治理**:未及时消费的交接按存量巡检逻辑提示疑似过期,不静默删除。

## 4. 范围

### In Scope(MVP)

- 新增记忆类型 `type: handoff`(短时任务状态,可核销)
  - 字段:`intent`(需求目标与动机)、`state`(分支/改动概览/已确认决策)、`next`(下一步清单+验收标准)、`repos`(涉及仓库/模块)、`lifecycle`(`active → consumed → 过期`)、`links`(关联记忆)
- 命令:`pensieve handoff`(从会话+git 状态提炼,draft 确认制)、`pensieve resume`(定位并展示 active handoff,消费后归档)
- 简报集成:`memory_context` 对当前项目展示 active handoff 横幅
- 治理复用:密钥扫描、local-only 守卫、语义查重全部沿用现有写入管线
- 同步:仅依赖现有 git sync,代码改动**仅同步 diff stat 概览**

### Out of Scope(明确不做)

- 全量会话记录同步(噪声过大,违反蒸馏哲学)
- 依赖 A 设备在线的远程回连方案(脆弱且有安全风险)v2 也不做
- 未提交代码 patch 包随库推送(MVP 不做;v2 可选且必须显式 opt-in)

## 5. 关键产品决策(已拍板)

1. **交接单元是一段"给未来自己的交接叙述"**,而非文件/会话副本——与 Pensieve"上下文即资产"定位一致。
2. **handoff 是可核销工单而非长期知识**:被 resume 消费后立即退出默认召回,避免污染搜索。
3. **捕获必须先于离开**:MVP 依赖显性动作("我下班了");v2 考虑会话关闭时零操作快照。绝不依赖回连 A 设备。
4. **合规红线默认收紧**:local-only 记忆绝不离开本机;patch 同步默认关闭。

## 6. 非功能需求

- **隐私安全**:handoff 写入复用密钥扫描(28+ 规则)与回显脱敏;含代码 patch 的 v2 能力必须显式 opt-in。
- **本地优先**:无新增网络依赖(LLM 网关与 git remote 除外)。
- **一致性**:handoff 消费/归档与记忆写入同 commit,避免中间态。

## 7. 风险与依赖

| 风险 | 应对 |
|---|---|
| 未提交代码不同步导致续接断档 | MVP 在 `next` 中显式列出"哪些文件改到哪";v2 opt-in patch 包 |
| patch 同步引发公司代码合规问题 | v2 默认关闭 + 密钥扫描 + 文档显著警告 |
| 交接文本与代码继续漂移后失真 | 过期巡检(复用锚点巡检思路)+ consumed 自动归档 |
| 公司代码托管平台禁止推送至个人远端 | 功能文档中明确建议:仅在自有远端使用 |

## 8. 里程碑

| 阶段 | 范围 | 判定标准(进入下一阶段) |
|---|---|---|
| MVP | handoff/resume 命令、记忆类型、简报横幅 | dogfood 2 周:周均使用 ≥ 2 次 且 resume 无需追问背景 |
| v2 | 会话关闭自动快照、多仓引用、patch 包(opt-in) | 依据 MVP 使用频率与合规反馈决策 |
